用户明确反馈："这几个暂时都不用拆分，我认为文件是比较独立且规整的。"

**规则**：行数超阈值（>1000/>1500）只是"关注信号"，不触发拆分提案。一个 1200 行但主题凝聚、章节连续、结构规整的文件是健康的知识沉淀，不该被拆散。

**Why**：用户对自己笔记的"规整度"有判断权。AI 凭机械阈值（行数/章节数）提案拆分，会打扰用户、且可能拆散本来凝聚的主题。2026-08-01 review 出 4 个超标文件（Redis 1216/RocketMQ 1052/subagents 1003/Agent开发实战 1130），用户判定都"规整独立"，全部不拆。2026-08-05 复查新增 3 个候选——热点账户高并发记账方案（1025 行）、Dubbo 与 RPC 框架横评（日期戳沉底）、MySQL B+树索引实现原理（日期戳沉底）——用户判定三者均独立、暂未深入，**维持不拆**。

**How to apply**：
- 规模超阈值 → 退出检查时一句话提示"该文件较大（N 行）"，点到为止，**不提案拆分**
- 结构违规（日期戳混合/章节跳号/单节过大/主题分散）→ 可提案**重组**（文件数不变），但判定保守，听用户的
- 拆分（一变多）→ **永不擅自提案**，除非用户主动说"拆一下""太长了拆开""把 X 独立出去"
- 详见 [[kb-content-style]] skill 的"文件拆分规则"段（已同步更新）
